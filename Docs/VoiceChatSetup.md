# Project Vector 음성채팅 연결 안내

작성 기준: 2026-10-13, 현재 프로젝트 구현 기준.

## 먼저 알아둘 것: 다른 컴퓨터에서는 무엇이 필요한가?

게임 서버를 실행하는 PC는 한 대만 정한다. 다른 PC들은 그 서버에 게임으로 접속한다. 각 PC에서 서버를 따로 켜면 같은 파티로 만날 수 없다.

| 구분 | 서버를 켜는 PC | 게임만 하는 PC |
|---|---|---|
| 최신 게임 클라이언트 | 게임도 할 경우 필요 | 필요 |
| 최신 게임 서버 실행 파일·서버 데이터 | 필요 | 불필요 |
| Vivox 인증정보 4개 입력 | 서버 실행 시 필요 | 불필요 |
| Vivox 토큰 키 보관 | 서버 관리자만 관리 | 전달하면 안 됨 |
| 인터넷 연결 | 필요 | 필요 |
| 마이크·스피커 설정 | 게임도 할 경우 필요 | 필요 |

**중요: 현재 클라이언트는 `127.0.0.1:9000`에 접속하도록 코드에 고정되어 있다. 이 주소는 항상 ‘그 게임을 실행하는 자기 컴퓨터’를 뜻한다. 다른 PC에 실행 파일만 복사한다고 서버에 연결되지는 않는다.**

아래 두 조건을 모두 맞춰야 한다.

1. 클라이언트가 같은 게임 서버에 접속할 것.
2. 서버가 Vivox 인증정보를 가지고 실행되어 있고, 각 클라이언트가 인터넷으로 Vivox에 연결할 수 있을 것.

게임 로그인 성공과 실제 음성 송수신 성공은 서로 다른 확인 항목이다.

## 1. PC 사용 방식 선택

### A. 지금 컴퓨터를 그대로 다른 집으로 가져가기

- 서버·게임 파일과 데이터가 그대로 있으면 현재 방식으로 사용할 수 있다.
- 서버를 종료했거나 PC를 재부팅했다면 아래 실행 도구로 다시 시작한다. 인증값은 다시 입력한다.
- 같은 PC 안에서 서버에 접속할 때는 `127.0.0.1`을 유지할 수 있다.
- 장소가 바뀌면 인터넷·방화벽·오디오 장치 상태가 달라질 수 있으므로 실제 통화 테스트를 다시 한다.

### B. 다른 PC가 서버 PC에 접속하기

- 서버는 한 대에서만 실행한다.
- 같은 신뢰할 수 있는 LAN 또는 구성된 신뢰할 수 있는 VPN을 사용한다.
- 게임만 하는 PC에는 최신 Windows 빌드 폴더 전체를 옮긴다. `.exe`만 옮기지 않는다. `_Data`, Unity 관련 DLL 등 빌드 산출물을 함께 복사한다.
- 클라이언트의 게임 서버 접속 주소를 서버 PC의 LAN/VPN 주소로 바꾸고 다시 빌드해야 한다.
- 서버 PC에서 게임도 한다면 그 클라이언트 역시 같은 서버를 가리키게 한다.
- 방화벽은 끄지 않는다. 필요하면 서버 프로그램/TCP 9000을 해당 신뢰 네트워크와 필요한 상대 PC에 한정해 허용한다.

현재 수정 위치는 Unity 프로젝트의 `Assets/Scripts/Network/NetworkManager.cs`, `client.Connect("127.0.0.1", 9000);` 부분이다. 실행 파일에서 주소를 바꾸는 설정 UI는 현재 없다. 소스를 바꿔도 이전 실행 파일에는 반영되지 않으므로 반드시 재빌드한다.

예: 실제 서버 LAN 주소가 `192.168.0.20`인 경우에만 다음처럼 사용한다. 예시 주소를 그대로 쓰지 않는다.

```csharp
client.Connect("192.168.0.20", 9000);
```

**주의: 현재 게임 TCP에는 TLS 암호화가 없다. 음성 접속 토큰도 이 연결로 받으므로, 공개 인터넷에 TCP 9000을 단순 포트포워딩하는 방식은 권장하지 않는다. 개발 테스트는 신뢰 LAN/VPN에서 한다. 공개 서비스에는 인증된 TLS/HTTPS 토큰 전달 구현이 먼저 필요하다.**

### C. 서버 자체를 새 PC로 옮기기

- 최신 서버 실행 파일과 필요한 실행 의존 파일, `Tools/StartVoiceServer.ps1`, 기존 서버 데이터 폴더를 옮긴다.
- 데이터 이전 전 서버를 정상 종료하고 백업한다. 실행 중인 CSV를 복사하거나 계정 파일을 빈 파일로 덮어쓰지 않는다.
- 새 PC의 실제 경로를 실행 명령에 넣는다. 기존 PC의 `C:\Users\GCT\...` 경로가 새 PC에도 있다고 가정하지 않는다.
- 같은 Unity 프로젝트의 Vivox 인증정보를 새 서버 실행 시 입력한다. PC가 바뀌었다고 새 Vivox 프로젝트를 만들 필요는 없다.
- 모든 클라이언트가 새 서버 주소를 바라보게 한다.

## 2. 서버 실행하기

### 준비할 네 가지 값

Unity Dashboard → 사용할 Project Vector 프로젝트 → Vivox → Voice and Text Chat → 인증정보.

| 실행 도구 질문 | 대시보드 항목 |
|---|---|
| `Vivox HTTPS server URL` | 서버 |
| `Vivox domain` | 도메인 |
| `Vivox token issuer` | 토큰 발급자 |
| `Vivox signing key` | 토큰 키 |

네 값은 모두 같은 프로젝트의 인증정보를 사용한다. 서버 주소의 `https://`를 포함해 값을 그대로 복사한다. 토큰 키는 채팅·스크린샷·Git·Unity 클라이언트에 넣지 않는다. 게임만 하는 사람에게 공유하지 않는다. 대시보드의 Access token enforcement 옵션을 이 안내를 따라 임의로 변경할 필요는 없다.

### 현재 PC용 실행 명령

기존 서버가 실행 중인지 먼저 확인한다. 같은 포트에 서버를 두 개 실행하지 않는다. PowerShell에서 실행한다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\GCT\Documents\GitHub\ProjectVectorServer\Tools\StartVoiceServer.ps1" -ServerExe "C:\Users\GCT\AppData\Local\Temp\VectorVoiceServer\ProjectVectorServer.exe" -DataDirectory "C:\Users\GCT\Documents\GitHub\ProjectVectorServer\ProjectVectorServer\ProjectVectorServer"
```

`Temp`에 있는 서버 파일은 임시 빌드다. 정리 작업으로 사라질 수 있으므로 다른 PC로 옮길 때는 지속적으로 사용할 서버 폴더에 복사하고 경로를 바꾼다.

### 새 PC용 명령 예시

아래는 경로 예시다. 실제 파일을 이 위치에 준비했을 때만 사용할 수 있다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\VectorServer\Tools\StartVoiceServer.ps1" -ServerExe "D:\VectorServer\ProjectVectorServer.exe" -DataDirectory "D:\VectorServer\Data"
```

`DataDirectory`는 기존 계정·프로필·게임 설정 CSV가 들어 있는 서버 데이터 폴더다. Unity의 `_Data` 폴더가 아니다.

질문마다 해당 값을 붙여넣고 Enter를 누른다. 마지막 토큰 키는 화면에 표시되지 않는 것이 정상이다.

```text
Game server started (PID ...); signing key was not written to disk.
```

이 메시지는 프로세스를 시작했다는 뜻이지, 로그인이나 실제 통화까지 성공했다는 뜻은 아니다. 도구는 키를 파일에 저장하지 않고 자식 서버 프로세스에만 전달한다. 서버를 다시 시작할 때도 이 도구로 입력한다. 서버 EXE를 그냥 더블클릭하면 이 도구에서 넣었던 인증값은 자동 복구되지 않는다.

## 3. 게임 접속부터 말하기까지

1. 양쪽 PC가 음성 기능이 포함된 최신 클라이언트를 사용한다. Unity에서는 Login 씬부터 시작한다.
2. 서로 다른 계정으로 같은 게임 서버에 로그인한다.
3. 한쪽에서 파티 초대를 보내고, 다른 쪽이 수락한다.
4. 양쪽에서 F10을 열어 상태가 `파티 음성`으로 바뀌는지와 참여자가 표시되는지 확인한다. 연결에는 시간이 걸릴 수 있다.
5. 마이크 켜짐, 입력 장치, 출력 장치, 음량, 상대방 개별 음소거 여부를 확인한다.
6. **F10 설정창과 채팅 입력창·팝업을 닫고 게임 화면을 활성화한 상태에서** 말한다.
7. 기본 모드는 `~` 키를 누르고 있는 동안 송신한다. 실제 입력은 키보드의 backquote 키이며 보통 Esc 아래, 숫자 1 왼쪽이다. Shift를 함께 누를 필요는 없다.
8. 키를 놓으면 송신을 멈춘다. F10에서 `자동 음성 감지`를 선택하면 키 없이 말할 수 있다. 설정창을 닫고 테스트한다.

현재는 설정창·채팅 입력·일부 팝업이 열렸거나 게임이 포커스를 잃으면 송신을 막는다. 이는 자동 음성 감지에도 적용된다. Alt+Tab으로 다른 앱에 간 동안에도 계속 송신하는 방식이 아니다. 게임으로 돌아온 뒤 PTT 키를 한 번 놓고 다시 누른다.

**한 PC에서 창 여러 개를 띄우면 포커스 제한과 같은 오디오 장치 때문에 실제 두 PC 테스트를 대체할 수 없다. 두 PC와 헤드셋을 사용하고 한 명씩 번갈아 말하는 방식으로 확인한다.**

## 4. 누구와 연결되는가?

### 참가자별 음량·음소거 UI

로비, 인게임, 결과 화면에서 F10 또는 음성 버튼으로 설정을 연다. 로비 팀 대기 화면에는 별도의 `팀 음성` 바로가기도 있다. 인게임에서 설정을 열면 커서가 풀리고 게임 조작 입력을 막는다. 닫으면 기존 커서 상태로 돌아간다.

- 왼쪽: 내 송신 방식, 마이크 음소거, 장치, 마이크 음량, 전체 듣는 음량.
- 오른쪽: 참가자 닉네임, 서버에서 확인한 프로필 아이콘, 말하는 중/음소거 상태, 사람별 듣는 음량과 음소거·초기화 버튼.
- 사람별 음량은 0~200% UI 범위이며 100%가 SDK 기본값이다. 0%는 들리지 않게 처리한다. 이는 SDK -50~50 조절값을 표시용으로 변환한 값이며 실제 음압이 정확히 두 배라는 의미는 아니다.
- 사람별 음량·음소거는 나에게 들리는 소리에만 적용한다. 상대방이나 다른 팀원의 설정을 바꾸지 않는다.
- 내 행은 왼쪽 마이크 설정으로 조절한다. 자기 목소리의 로컬 청취 슬라이더는 표시하지 않는다.
- 사람별 설정은 이 PC의 내 Vivox 계정과 상대 Vivox 계정 조합으로 저장한다. 재입장/재연결 후 다시 적용되며, 설정창을 닫거나 게임을 정상 종료할 때 음량 설정이 디스크에 저장된다. 초기화는 해당 상대를 100%·음소거 해제로 되돌린다.
- 다른 PC로 설정을 자동 동기화하는 서버 저장 기능은 아니다. 새 PC에서는 기본값부터 다시 맞춘다.
- 프로필 정보가 아직 도착하지 않았다면 잘못된 아이콘을 대신 보여주지 않고 빈 아이콘 배경으로 표시한다.

| 상황 | 현재 연결 정책 |
|---|---|
| 초대만 보냄, 상대 미수락 | 아직 같은 파티 음성이 아님 |
| 로비에서 2명 이상 파티 구성 | 같은 파티원끼리 연결 |
| 일반·랭크 경기 | 같은 팀끼리 연결, 죽은 팀원 포함 |
| 상대 팀 | 같은 팀 음성에 참가할 수 없음 |
| 결과 화면 | 경기 팀 음성에서 나옴 |
| 로비 복귀 | 파티가 유지되어 있으면 파티 음성에 다시 연결 |
| 파티 나가기·연결 끊김 | 기존 음성 권한을 갱신하고 연결/송수신 정리 |
| 사설방·관전자 | 현재 지원하지 않음 |

## 5. 다른 PC에서 안 될 때: 위에서부터 확인

### ① 게임 로그인부터 안 되는가?

음성 이전에 게임 서버 연결 문제부터 확인한다.

- 클라이언트가 여전히 `127.0.0.1`인 예전 빌드는 아닌가?
- 실제 서버 PC 주소로 변경한 빌드인가? 두 PC가 같은 서버를 보고 있는가?
- 서버가 실행 중이고 LAN/VPN이 연결되어 있는가?
- 방화벽의 해당 프로그램/포트 허용 범위가 맞는가?

게임만 하는 PC에서 다음 읽기 전용 연결 검사를 할 수 있다. 예시 IP를 실제 서버 주소로 교체한다.

```powershell
Test-NetConnection -ComputerName 192.168.0.20 -Port 9000
```

`TcpTestSucceeded: True`는 TCP 포트에 닿았다는 뜻이다. 게임 인증, 올바른 서버 버전, Vivox 또는 음성 송수신 성공까지 보장하지 않는다.

### ② 게임은 되는데 음성 연결이 안 되는가?

| F10 상태/증상 | 우선 확인할 것 |
|---|---|
| F10 화면 자체가 없음 | 음성 구현 전의 구버전 빌드인지, Login부터 시작했는지 |
| `음성 서비스 준비 중` | 서버를 전용 도구로 실행했는지, 인증정보 4개가 빠지거나 잘못되지 않았는지 |
| `같은 파티·팀에 들어가면 음성 연결` | 상대가 초대를 수락했는지, 파티가 2명 이상인지, 지원되는 모드인지 |
| `음성 연결 실패 · 잠시 후 재시도` | 같은 프로젝트 인증값인지, 인터넷/Vivox 연결이 차단되지 않았는지, PC 시간이 맞는지 |
| `음성 연결 끊김 · 다시 연결 중` | 게임 서버 연결 및 최신 서버/클라이언트 버전, 네트워크 상태 |
| `음성 연결 지연` | 잠시 기다려도 지속되는지 확인 후 상태 문구와 발생 단계를 기록 |

인증값을 바꾸었다면 서버를 다시 실행해야 한다. 게임 로그인이 된다고 서버에 Vivox 인증값까지 정상 입력되었다고 볼 수는 없다.

### ③ `파티 음성`인데 소리가 안 들리는가?

- 양쪽 F10에 서로 참여자로 표시되는지 확인한다.
- Windows 자체 마이크 입력 테스트가 되는지 확인한다. Windows 설정의 마이크 접근 권한, 특히 데스크톱 앱 접근 허용 여부도 확인한다.
- USB/블루투스 장치를 바꿨다면 F10에서 올바른 입력·출력 장치를 다시 선택한다. 장치 설정은 PC마다 다를 수 있다.
- 마이크 음소거와 상대방 개별 음소거를 해제하고 입력·출력 음량을 확인한다.
- 설정창과 채팅창을 닫고 게임 화면에 포커스를 둔다.
- PTT 키를 놓았다가 다시 누른 채 말한다. 자동 모드라면 말할 때만 감지되는지 확인한다.
- 송신자의 말하는 중 표시와 수신자의 실제 소리를 따로 확인한다. 표시만 움직인다고 상대방의 출력 장치까지 정상이라는 뜻은 아니다.
- A→B와 B→A를 각각 확인한다. 한 방향만 들리면 안 들리는 방향의 마이크/스피커 설정을 우선 확인한다.
- 방화벽·보안 프로그램을 전부 끄지 않는다. 조직/학교 네트워크라면 음성 서비스 차단 여부를 관리자에게 확인한다.

## 6. ‘다른 컴퓨터에서도 된다’고 판단할 최소 테스트

- [ ] 두 PC가 같은 최신 게임 서버에 로그인된다.
- [ ] 파티 초대 수락 후 양쪽에 `파티 음성`과 참여자가 표시된다.
- [ ] A가 PTT로 말하면 B에게 들리고, A가 키를 놓으면 송신이 멈춘다.
- [ ] B가 PTT로 말하면 A에게도 들린다.
- [ ] 자동 음성 감지, 마이크 음소거, 상대 음소거가 각각 작동한다.
- [ ] 일반/랭크 진입 시 같은 팀으로 전환되고 상대 팀 음성이 섞이지 않는다.
- [ ] 파티 나가기, 재초대, 결과 화면, 로비 복귀 후 연결 상태가 맞다.
- [ ] 게임 재실행과 서버 재실행 후에도 같은 절차로 재연결된다.

현재 완료된 것은 서버 빌드, Unity 컴파일, 서버의 토큰·파티/팀 접근 정책 자동 검사다. 서버 실행 메시지도 사용자에게서 확인했다. **실제 두 PC의 마이크 송수신 성공은 아직 확인하지 않았다. 위 체크리스트는 통과 기록이 아니라 앞으로 확인할 항목이다.**

## 7. 문제를 전달할 때 남길 정보

아래 내용을 보내면 ‘안 된다’에서 원인을 좁힐 수 있다.

- 서버 PC와 게임 PC가 같은 컴퓨터인지, 서로 다른 컴퓨터인지.
- 같은 LAN인지 VPN인지, 게임 로그인은 가능한지.
- 양쪽이 최신 빌드인지, Unity 실행이라면 Login부터 시작했는지.
- 초대 수락 전/후 또는 경기 중 어느 단계인지.
- 양쪽 F10의 상태 문구와 참여자 표시, 선택한 장치 이름.
- A→B와 B→A 중 어느 쪽 소리가 안 들리는지.
- 발생 시각과 오류 문구. 키·접속 토큰·개인정보는 가린다.

Windows 플레이어 로그의 기본 확인 위치는 `%USERPROFILE%\AppData\LocalLow\DefaultCompany\Project Vector\Player.log`다. 회사/제품 이름이나 로그 실행 옵션이 변경되면 경로도 달라질 수 있다. 로그 전체를 외부에 공개하기 전에 비밀값과 개인정보가 있는지 확인한다.
